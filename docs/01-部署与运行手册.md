# ClkLog 部署与运行手册

> 面向读者：熟悉 Android 开发、但没有 Java 后端部署经验的工程师。
> 目标：从零把 ClkLog 社区版跑起来 —— 先本地跑通，再打包，最后上生产。
> 本文所有命令、端口、环境变量均来自对源码的逐文件核对（版本 1.3.1），不是通用模板。

---

## 0. 先看结论：你要跑的是 6 个东西

ClkLog 不是一个单体应用，而是 **6 个独立仓库** 组成的微服务群，仓库根目录用 Git Submodule 把它们串起来：

| 目录 | 仓库 | 作用 | 技术栈 | 默认端口 |
|---|---|---|---|---|
| `receiver/` | clklog-receiver | **数据接收服务**：SDK 上报的数据从这里进（`/api/gp`） | Spring Boot 2.6.4 / JDK8 | 8080 |
| `processing/` | clklog-processing | 数据加工（Kafka → ClickHouse），**社区版可不用** | Flink 1.16.1 / JDK8 | 无 HTTP |
| `init/` | clklog-init | **建表 + 定时聚合**：跑 ClickHouse 建表脚本、按分钟刷新统计表 | Spring Boot / JDK8 | 8080 |
| `manage/` | clklog-manage | 管理后台接口：登录、项目、用户、密钥、全局设置 | Spring Boot 2.6.4 / JDK8 | 8080 |
| `api/` | clklog-api | 统计查询接口：61 个报表接口，前端所有图表的数据来源 | Spring Boot 2.6.4 / JDK8 | 8080 |
| `ui/` | clklog-ui | 前端页面（Vue2 + Element UI），打包后是纯静态文件 | Node 14 + nginx | 80 |

依赖的中间件：

| 组件 | 用途 | 是否必须 | 建议版本 |
|---|---|---|---|
| **MySQL** | 存项目、用户、密钥、全局设置等「元数据」 | 必须 | 5.7 / 8.0 |
| **ClickHouse** | 存全部埋点明细 + 统计汇总表（核心） | 必须 | 22.8 LTS 及以上 |
| **Redis** | 登录 token、项目配置缓存、IP 地域缓存、API Key 缓存 | 必须 | 5.0+ |
| **Kafka** | 削峰队列（仅 `enable-simple-version=false` 时用） | 可选 | 2.x+ |

> **给新手的建议**：先用 Docker 起 MySQL / ClickHouse / Redis 三个中间件，Java 服务直接用 `java -jar` 在本机跑。这条路径最短、最容易排错。等跑通了再考虑 Docker 化。

## 1. 数据是怎么流动的（理解这张图，排错就有方向）

```
   Web / Android / iOS / 小程序 SDK
                │  HTTP POST  /api/gp  (data_list = Base64(JSON))
                ▼
        ┌───────────────┐
        │ clklog-receiver│  校验 project / token，解析 UA、IP 地域
        └───────┬───────┘
                │
      enable-simple-version = true（社区版默认）
                │  直接批量 INSERT
                ▼
        ┌──────────────────────────────┐
        │ ClickHouse: clklog.log_analysis │  ← 明细表（所有原始事件）
        └──────────────┬───────────────┘
                       │  clklog-init 定时轮询（间隔 5 分钟），顺序执行 18 个聚合 SQL
                       ▼
        ┌──────────────────────────────┐
        │ ClickHouse: *_bydate 等汇总表  │
        └──────────────┬───────────────┘
                       │  SELECT
                       ▼
        ┌──────────────┐        ┌────────────────┐
        │ clklog-api   │◄───────┤ clklog-ui(nginx)│
        └──────────────┘        └───────┬────────┘
                                        │ 登录 / 项目管理 / 密钥
                                        ▼
                              ┌──────────────────┐
                              │ clklog-manage    │──► MySQL（clklog 库）
                              └──────────────────┘──► Redis（ProjectSettingKey 等）
```

三个关键联动点，务必记住：

1. **receiver 不认识 MySQL**。它判断「项目是否存在」靠的是 Redis 里的 `ProjectSettingKey`，而这个 key 由 **manage 服务每 30 秒刷新一次**。所以：**manage 没启动 / 没连上 Redis，上报就会返回 `project_not_exist`**。
2. **api 和 manage 必须共用同一个 `token_secret` 和同一个 Redis**。manage 签发 JWT，api 校验 JWT，secret 不一致就会出现「后台能登录、图表全 401」。
3. **明细进库 ≠ 立刻能看报表**。`clklog-init` 是定时聚合，数据进 `log_analysis` 后要等它跑完一轮（默认一轮 5 分钟，脚本之间还各 sleep 7 秒），报表才有数。

## 2. 端口规划（本机全跑必须改端口）

四个 Java 服务的 `application.yml` 里 `server.port` 全是 `8080`，同一台机器上必须用启动参数错开。本文统一采用下面的规划：

| 服务 | 容器内端口 | 本机/宿主机端口 | 对外访问 |
|---|---|---|---|
| clklog-ui (nginx) | 80 | 80 | `http://your-domain/` |
| clklog-manage | 8080 | **8081** | `http://your-domain/manage/` |
| clklog-api | 8080 | **8082** | `http://your-domain/api/` |
| clklog-receiver | 8080 | **8083** | `http://your-domain:8083/api/gp` |
| clklog-init | 8080 | 8084（可不暴露） | 内部调用 |
| MySQL | 3306 | 3306 | 内部 |
| ClickHouse | 8123 (HTTP) / 9000 (TCP) | 8123 / 9000 | 内部 |
| Redis | 6379 | 6379 | 内部 |

> ⚠️ **一个必须提前知道的坑**：前端请求走 `/api/*`（代理到 clklog-api），而 SDK 上报走 `/api/gp`（代理到 clklog-receiver）。**两者路径前缀冲突**。所以生产环境强烈建议给 receiver 一个**独立端口或独立域名**（如 `collect.your-domain.com`），不要让它们共用同一个 `/api` 前缀。

## 3. 环境准备

### 3.1 必装

| 工具 | 版本要求 | 校验命令 | 说明 |
|---|---|---|---|
| JDK | **必须 8**（1.8） | `java -version` | 四个 Java 服务 `maven.compiler.target=1.8`，镜像基础是 `openjdk:8u342-jdk`。用 11/17 编译或运行大概率报错 |
| Maven | 3.6+ | `mvn -v` | 也可以直接用 IDEA 自带的 Maven |
| Node.js | **14.15.0**（推荐） | `node -v` | 前端是 vue-cli 4 + webpack 4，Node 16+ 容易在 OpenSSL 上报 `ERR_OSSL_EVP_UNSUPPORTED` |
| Docker | 任意较新版本 | `docker -v` | 起中间件用，可选但强烈建议 |

macOS 上装 JDK 8 与 Node 14：

```bash
# JDK 8（任选一种）
brew install --cask temurin@8
# 或使用 sdkman：sdk install java 8.0.392-tem

# Node 14.15.0
brew install nvm
nvm install 14.15.0
nvm use 14.15.0
```

### 3.2 磁盘与内存

- ClickHouse 建议 ≥ 4C8G，数据盘按「日活 × 事件数 × 0.5KB」估算。
- 本机开发跑全套（含 ClickHouse）建议给 Docker 至少 6GB 内存。

## 4. 第一步：用 Docker 起三个中间件

```bash
# 1) MySQL 8.0
docker run -d --name clklog-mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=clklog123 \
  -e TZ=Asia/Shanghai \
  mysql:8.0 \
  --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci

# 2) ClickHouse 22.8 LTS（社区版用到的 MergeTree / ReplacingMergeTree / Atomic 库引擎，22.8 完全支持）
docker run -d --name clklog-clickhouse \
  -p 8123:8123 -p 9000:9000 \
  -e TZ=Asia/Shanghai \
  clickhouse/clickhouse-server:22.8

# 3) Redis 7
docker run -d --name clklog-redis \
  -p 6379:6379 \
  redis:7 redis-server --appendonly yes
```

验证：

```bash
docker ps
curl http://127.0.0.1:8123/ping          # 期望返回 Ok.
redis-cli -h 127.0.0.1 ping              # 期望返回 PONG
docker exec -it clklog-mysql mysql -uroot -pclklog123 -e "select version();"
```

> ClickHouse 的 `default` 用户默认**没有密码**，所以下面所有 `clickhouse_pass` 都留空。
> JDBC 连的是 **8123（HTTP 端口）**，不是 9000。这是新手最常踩的坑之一。

## 5. 第二步：初始化数据库

### 5.1 MySQL（手动导入，必须做）

建库建表脚本在 `init/scripts_init/mysql/mysql_clklog.sql`，它做了这些事：

- 创建数据库 `clklog`（`utf8` / `utf8_general_ci`）
- 创建 8 张表：`tbl_project`、`tbl_project_log_stat`、`tbl_project_stat`、`tbl_global_setting`、`tbl_api_key`、`sys_operrecord`、`sys_user`、`sys_userlogin`
- 插入默认项目 `clklogapp`（token：`ddf51db3-7c99-1310-a44f-79feb7b63c69`）
- 插入两个默认账号：`admin`、`clklog`
- 插入一条全局设置记录

```bash
mysql -h 127.0.0.1 -P 3306 -u root -pclklog123 < init/scripts_init/mysql/mysql_clklog.sql

# 验证
mysql -h 127.0.0.1 -u root -pclklog123 -e "use clklog; show tables; select username from sys_user;"
```

> **默认登录账号：`admin` / `clklog`**（另一个预置账号 `clklog` / `clklog`）。首次登录后请立即在「账号管理」里改密码。

### 5.2 ClickHouse（不用手动做，init 服务会自动建）

`init/scripts/init.sql` 会创建：

- 数据库 `clklog`（`ENGINE = Atomic`，库名由 `init.log-db` 配置，默认 `clklog`）
- 明细表 `log_analysis`（MergeTree）
- 18 张汇总表：`visituri_summary_bydate`、`flow_trend_bydate`、`flow_trend_byhour`、`searchword_detail_bydate`、`channel_detail_bydate`、`device_detail_bydate`、`sourcesite_detail_bydate`、`user_pv_bydate`、`user_visit_bydate`、`user_visittime_bydate`、`visitor_detail_bydate`、`visitor_life_bydate`、`area_detail_bydate`、`visituri_detail_bydate`、`visitor_detail_byinfo`、`visitor_detail_bysession`、`visitor_summary_byvisitor`、`crashed_detail_bydate`

这些 SQL 里带 `${CLKLOG_LOG_DB}` 占位符，由 `clklog-init` 启动时替换成实际库名后执行，所以**正常流程不需要手工执行**。

如果确实要手工建（比如想先确认表结构）：

```bash
sed 's/${CLKLOG_LOG_DB}/clklog/g' init/scripts/init.sql > /tmp/init_ck.sql
docker exec -i clklog-clickhouse clickhouse-client --multiquery < /tmp/init_ck.sql
```

## 6. 第三步：确认源码已就位

`api/ init/ manage/ processing/ receiver/ ui/` 这六个目录是以 **Git Submodule** 形式引用的，`.gitmodules` 里写的是相对地址 `../clklog-api.git`，指向 fork 者自己的命名空间，通常并不存在，所以直接 `git clone` 主仓库时它们是空的。

**当前工作区已经补齐**（2026-10-20 从官方 `github.com/clklog/*` 拉取，版本与主仓库锁定的 submodule commit 一致，均为 **v1.3.1**）：

| 目录 | 来源仓库 | 锁定 commit | 文件数 |
|---|---|---|---|
| `api/` | clklog-api | `b68e47a` | 283 |
| `init/` | clklog-init | `04e6b10` | 42 |
| `manage/` | clklog-manage | `b175d7e` | 134 |
| `processing/` | clklog-processing | `94214ab` | 36 |
| `receiver/` | clklog-receiver | `a93e51f` | 44 |
| `ui/` | clklog-ui | `51bbeaa` | 308 |

验证一下：

```bash
ls api/pom.xml manage/pom.xml init/pom.xml receiver/pom.xml processing/pom.xml ui/package.json
ls init/scripts_init/mysql/mysql_clklog.sql      # MySQL 建表脚本
ls receiver/iplib/                               # IP2Location 地域库
ls manage/setting/                               # 国家城市中英文对照表
```

> ⚠️ **这两点要知道**：
> 1. 这些文件是**按 commit 下载的源码压缩包解压**而来，目录里**没有 `.git`**，所以它们不是可提交的 git 仓库。`git status` 里看不到它们（父仓库仍把六个目录当成未初始化的 submodule），**不会污染主仓库**。
> 2. 如果你后续要 `git pull` 更新主仓库、或想用 git 管理这些子模块，等网络能访问 GitHub 的 git 协议后，用下面的方式重来一次即可：

```bash
# 标准方式（网络正常时）
git submodule update --init --recursive

# 若 .gitmodules 里的相对地址失效，先覆盖成官方地址
git config submodule.api.url        https://github.com/clklog/clklog-api.git
git config submodule.init.url       https://github.com/clklog/clklog-init.git
git config submodule.manage.url     https://github.com/clklog/clklog-manage.git
git config submodule.processing.url https://github.com/clklog/clklog-processing.git
git config submodule.receiver.url   https://github.com/clklog/clklog-receiver.git
git config submodule.ui.url         https://github.com/clklog/clklog-ui.git
git submodule sync && git submodule update --init --recursive
```

## 7. 第四步：本地源码运行（推荐路径）

### 7.1 环境变量总表（照着填，别漏）

四个服务全部通过环境变量注入配置，`application.yml` 里没有默认值，**缺一个就启动失败**。

| 变量名 | 用于 | 示例值 | 说明 |
|---|---|---|---|
| `clickhouse_host` | api / manage / init / receiver | `127.0.0.1` | |
| `clickhouse_port` | 同上 | `8123` | HTTP 端口 |
| `clickhouse_user` | 同上 | `default` | |
| `clickhouse_pass` | 同上 | 空 | 默认无密码 |
| `redis_host` | api / manage / receiver | `127.0.0.1` | init 不需要 Redis |
| `redis_port` | 同上 | `6379` | |
| `mysql_host` | **仅 manage** | `127.0.0.1` | |
| `mysql_port` | **仅 manage** | `3306` | |
| `mysql_user` | **仅 manage** | `root` | |
| `mysql_pass` | **仅 manage** | `clklog123` | |
| `token_secret` | **api + manage，必须一致** | `clklog-secret-2024` | JWT 签名密钥 |
| `SPRING_SECURITY_USER_NAME` | **仅 api** | `admin` | actuator 健康检查的 Basic 认证用户名 |
| `SPRING_SECURITY_USER_PASSWORD` | **仅 api** | `clklog` | 同上 |
| `SPRING_KAFKA_BOOTSTRAP_SERVERS` | receiver | `127.0.0.1:9092` | **仅当 `enable-simple-version=false` 时才需要** |

建议写一个 `env.sh` 放在仓库根目录，`source` 一次全局生效：

```bash
# env.sh
export clickhouse_host=127.0.0.1
export clickhouse_port=8123
export clickhouse_user=default
export clickhouse_pass=
export redis_host=127.0.0.1
export redis_port=6379
export mysql_host=127.0.0.1
export mysql_port=3306
export mysql_user=root
export mysql_pass=clklog123
export token_secret=clklog-secret-2024
export SPRING_SECURITY_USER_NAME=admin
export SPRING_SECURITY_USER_PASSWORD=clklog
```

### 7.2 启动顺序（重要）

**init → manage → api → receiver → ui**

- init 要先建表，后面的服务才有表可读；
- manage 要先跑起来往 Redis 写 `ProjectSettingKey`，receiver 才能认项目；
- ui 最后起。

### 7.3 逐个启动

```bash
source env.sh

# ① clklog-init：必须在 init/ 目录下运行（它要读 ./scripts/*.sql）
cd init
mvn clean package -DskipTests
java -jar target/clklog-init-1.3.1.jar --server.port=8084
# 日志出现 initDb 成功、以及 "insert token left ..." 说明建表完成、聚合轮询已开始

# ② clklog-manage：必须在 manage/ 目录下运行（它要读 ./setting/*.txt 国家城市对照表）
cd ../manage
mvn clean package -DskipTests
java -jar target/clklog-manage-1.3.1.jar --server.port=8081

# ③ clklog-api：目录无所谓，但建议也在 api/ 下
cd ../api
mvn clean package -DskipTests
java -jar target/clklog-api-1.3.1.jar --server.port=8082

# ④ clklog-receiver：必须在 receiver/ 目录下运行（它要读 ./iplib/*.BIN IP 库）
cd ../receiver
mvn clean package -DskipTests
java -jar target/clklog-receiver-1.3.1.jar --server.port=8083
```

> **为什么一定要「在各自目录下」运行？**
> 源码里用 `System.getProperty("user.dir")` 拼资源路径：
> - init 找 `user.dir/scripts/init.sql`
> - manage 找 `user.dir/setting/city-eng-chs-map.txt`
> - receiver 找 `user.dir/iplib/IP2LOCATION-LITE-DB3.BIN`
>
> 换到别的目录 `java -jar` 就会读不到文件，表现为「init 一直不建表」「城市名全是英文」「地域分析全空」。
> 也可以用参数指定：init 用 `--init.resource-path=/abs/path`，receiver 用 `--receiver.resource-path=/abs/path`；manage 没有该开关，只能靠工作目录。

### 7.4 用 IDEA 跑（更舒服）

1. `File → Open`，分别打开 `api/`、`manage/`、`init/`、`receiver/`（IDEA 会把每个 pom 识别为独立 Maven 工程）。
2. 在 `Run/Debug Configurations` 里新建 Spring Boot 配置，Main class 分别是：
   - `com.zcunsoft.clklog.App`（api）
   - `com.zcunsoft.clklog.ManageApp`（manage）
   - `com.zcunsoft.App`（init / receiver 的入口类也叫 `App`，注意区分模块）
3. **Working directory 一定要设成对应模块目录**（见上面的说明）。
4. 在 `Environment variables` 里把 `env.sh` 里的变量逐个填进去。
5. `Program arguments` 填 `--server.port=8081` 之类的端口覆盖。

### 7.5 前端本地开发

```bash
cd ui
nvm use 14.15.0
npm install --registry=https://registry.npmmirror.com
```

开发前先改 `ui/vue.config.js` 里的代理目标（源码里写的是占位符 `YOUR_DOMAIN`，不改必 404）：

```js
function setProxy(env) {

```


## 8. 第五步：打包

### 8.1 Java 服务打可执行 jar

三个 Spring Boot 服务（api / manage / init / receiver）的 pom 都配了 `spring-boot-maven-plugin`，直接：

```bash
cd api && mvn clean package -DskipTests
# 产物：target/clklog-api-1.3.1.jar（可直接 java -jar 运行，内含 Tomcat）
# 同时会生成 target/clklog-api-1.3.1.jar.original（不要用这个）
```

四个服务的产物名：

| 服务 | 产物 |
|---|---|
| api | `target/clklog-api-1.3.1.jar` |
| manage | `target/clklog-manage-1.3.1.jar` |
| init | `target/clklog-init-1.3.1.jar` |
| receiver | `target/clklog-receiver-1.3.1.jar` |

### 8.2 processing（Flink 作业，社区版可跳过）

它用的是 `maven-assembly-plugin`，产物是带全部依赖的胖包：

```bash
cd processing && mvn clean package -DskipTests
# 产物：target/clklog-processing-1.3.1-jar-with-dependencies.jar
# 主类：com.zcunsoft.clklog.analysis.entry.JieXiJson
```

部署方式是提交给 Flink 集群，而不是 `java -jar`：

```bash
flink run -c com.zcunsoft.clklog.analysis.entry.JieXiJson \
  clklog-processing-1.3.1-jar-with-dependencies.jar
```

注意它读的是 **工作目录下的 `config.properties`**（`user.dir/config.properties`），里面有 kafka 地址、checkpoint 路径、并行度等，需要按你的环境改。

> 社区版默认 `receiver.enable-simple-version=true`，数据直接从 receiver 写 ClickHouse，**不需要 Kafka 也不需要 processing**。只有数据量大、想做削峰和失败重投时，才把它关掉走 Kafka 链路。

### 8.3 前端打包

```bash
cd ui
nvm use 14.15.0
npm install
npm run build        # 产物在 dist/
```

**打包前必须改 `ui/public/config.js`**，这是生产环境的运行时配置（nginx 直接把文件吐给浏览器，改完不用重新 build 也能生效）：

### 8.4 打成 Docker 镜像

每个仓库根目录都有 `Dockerfile`，都通过 `ARG` 接收构建产物路径，所以 **构建上下文必须是仓库根目录**：

```bash
# clklog-api（Dockerfile 里还会 COPY ./sql/* 和 docker-entrypoint.sh，所以不能只传 target/）
```

## 9. 第六步：生产部署

### 9.1 nginx 配置（前端 + 反向代理）

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /usr/share/nginx/html;
    index index.html;

    # 前端单页应用，必须回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 统计查询接口 → clklog-api（注意结尾的 / 会剥掉 /api 前缀）
    location /api/ {
        proxy_pass http://127.0.0.1:8082/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 管理接口 → clklog-manage
    location /manage/ {
        proxy_pass http://127.0.0.1:8081/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 如果确实要让上报接口和前端共用 80 端口，加这条更精确的规则（必须放在 /api/ 之前）
    # location = /api/gp {
    #     proxy_pass http://127.0.0.1:8083/api/gp;
    #     proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    # }
}
```

> `proxy_set_header X-Forwarded-For` 必须加：receiver 靠它取真实客户端 IP 做地域分析（代码里依次取 `x-forwarded-for` → `Proxy-Client-IP` → `WL-Proxy-Client-IP` → `remoteAddr`）。不加的话所有访客都会被算成 nginx 的内网 IP。

## 11. 常见问题（新手 90% 会遇到的）

### 11.1 上报返回 `project_not_exist`

receiver 判断项目是否存在，靠的是 Redis 里的 `ProjectSettingKey`（一个 JSON，由 manage 每 30 秒写入一次）。

排查顺序：

1. manage 起了吗？`docker compose ps`
2. manage 连上 Redis 了吗？`redis-cli get ProjectSettingKey` 应该有内容
3. MySQL 里 `tbl_project` 有没有这个 `project_name`？上报的 `project` 参数必须和表里的 `project_name` **完全一致**（默认是 `clklogapp`）

### 11.2 上报返回 `parse_data_failed`

- `data` / `data_list` 为空
- Base64 解不开（注意是**标准 Base64**，不是 URL-safe）
- `gzip=1` 但数据其实没压缩（或反过来）
- 解出来的不是合法 JSON

### 11.3 后台能登录，但所有图表 401 / 403

`token_secret` 在 manage 和 api 里不一致。两边必须完全相同，且共用同一个 Redis（token 存在 Redis 里）。

### 11.4 `clklog-init` 起来了但 ClickHouse 里没表

99% 是工作目录不对，读不到 `scripts/init.sql`。看日志里有没有 `initDb error`，然后确认是 `cd init && java -jar ...`。

### 11.5 数据进库了，但报表一直是 0

- 聚合是**定时**的：一轮之间间隔 5 分钟（`init.sleep-millisec-after-one-round`），而一轮里 18 个脚本每个之间还要 sleep 7 秒，**整轮跑完约 2 分钟**，所以从数据入库到报表可见，最坏要等 7 分钟左右；
- 聚合只统计 **`stat_date = 今天`** 的数据，昨天的数据不会回补；
- 事件类型不对：PV 只认 `$pageview`（js）、`$AppViewScreen`（Android/iOS）、`$MPViewScreen`（小程序）。自定义事件不会计入 PV。

### 11.6 端口冲突 / 启动报 `Port 8080 was already in use`

四个服务默认都是 8080，必须逐个用 `--server.port=` 错开。

### 11.7 ClickHouse 连不上

- JDBC 用的是 **8123**（HTTP），不是 9000（TCP Native）
- `clickhouse_pass` 留空时要写成 `""`，不能写成 `null`
- 检查 `curl http://127.0.0.1:8123/ping`

### 11.8 前端页面空白 / 接口 404

- 打开浏览器 Network，看请求地址是 `http://your-domain/api/xxx` 还是别的；
- 检查 `public/config.js` 里的 `BASE_API` / `BASE_API_MANAGE`；
- 检查 nginx 的 `proxy_pass` 结尾有没有 `/`（少了 `/` 不会剥前缀，后端会收到 `/api/flow/getFlow` 这种多一层的路径，直接 404）。

### 11.9 时区差 8 小时

- 容器统一加 `TZ=Asia/Shanghai`
- MySQL JDBC 串里已经带了 `serverTimezone=GMT+8`（写死在 `application.yml`，不用改）
- 上报的 `time` 必须是**毫秒时间戳**

### 11.10 地域分析全空 / 城市名是英文

- receiver 的 `iplib/*.BIN` 没读到（工作目录不对）
- manage 的 `setting/city-eng-chs-map.txt` 没读到（工作目录不对，或 Docker 里没挂载 `/setting`）

## 12. 备份、升级与日常运维

### 12.1 备份

```bash
# MySQL 元数据（项目、账号、密钥）—— 小，每天备
mysqldump -h127.0.0.1 -uroot -pclklog123 --single-transaction clklog > clklog_$(date +%F).sql

# ClickHouse 明细数据 —— 大，按需备
# 方案 A：冷备数据目录
docker run --rm -v clklog_clickhouse_data:/data -v $(pwd):/backup alpine \
  tar czf /backup/clickhouse_$(date +%F).tar.gz -C /data .
# 方案 B：导出单表
clickhouse-client -q "SELECT * FROM clklog.log_analysis FORMAT Native" > log_analysis.native
```

### 12.2 升级

1. 停 receiver（先停止写入）
2. 备份 MySQL + ClickHouse
3. 逐个替换 jar / 镜像（版本号同步升，四个服务版本号一致更安全）
4. `clklog-init` 会重新执行 `init.sql`，脚本全是 `CREATE TABLE IF NOT EXISTS`，**不会删数据**，但**不会自动加字段**——跨大版本升级前务必看官方升级说明
5. 起 receiver → 起 manage → 起 api

### 12.3 关键 Redis Key（排错用）

| Key | 写入方 | 用途 |
|---|---|---|
| `ProjectSettingKey` | manage（30s） | 项目配置，receiver/api 都读它 |
| `ClientIpRegionHash` | receiver | IP → 国家/省/市 缓存（默认 7 天过期） |
| `CityEngChsMapKey` | manage（60s） | 城市中英文对照 |
| `clklog:apikey:<key>` | manage | API Key 鉴权缓存 |

## 13. 一张表总结：我要改配置该动哪里

| 想改什么 | 改哪里 |
|---|---|
| 端口 | 启动参数 `--server.port=` |
| 数据库地址 | 环境变量 `mysql_host` / `clickhouse_host` / `redis_host` |
| 登录密钥 | 环境变量 `token_secret`（api + manage 同步改） |
| ClickHouse 库名 | `init` 的 `--init.log-db=`（默认 `clklog`） |
| 聚合频率 | `init` 的 `--init.quartz.*`（cron 表达式）、`--init.sleep-millisec-after-one-round=` |
| 是否走 Kafka | `receiver` 的 `--receiver.enable-simple-version=false` |
| 是否校验项目 token | `receiver` 的 `--receiver.enable-check-project-token=true` |
| 单次上报大小上限 | `receiver` 的 `--receiver.max-request-size=2097152`（默认 2MB） |
| 前端接口地址 | `ui/public/config.js` |
| 开发环境代理 | `ui/vue.config.js` 的 `setProxy()` |
| 默认项目 | MySQL `tbl_project` 表 |
